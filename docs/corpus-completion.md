# 语料补全计划与实施记录（v2）

> 状态：**v2 已合入本地语料并完成评测**（2026-10-02）。语料文件与片段不入仓库（.gitignore），本文档记录计划、来源留痕与实测数字；获取与转换代码在仓库（`scripts/docx_to_articles.py`）。

## 0. 背景与缺口

v1 语料（14,212 条，238 部）源自 legal-wisdom 的公报 PDF 解析库，三类缺口：

1. **覆盖缺口**：民法典、刑法、行政处罚法、劳动合同法、劳动法、刑事诉讼法等最常被问到的法律正文缺失（源头库就没有）；
2. **质量缺口**：公报双栏 PDF 交错解析造成乱序污染（见 README「已知失败案例」）；
3. **口径缺口**：修订版本并存、行号标签偏移。

## 1. 补全策略（本次实施的部分）

**来源**：国家法律法规数据库 flk.npc.gov.cn（全国人大官方库，发布《中华人民共和国民法典》等法律的权威机构）。选官方 docx 而非 PDF：原生文本零解析残片、单栏无交错，从源头规避 v1 的两类解析污染。

**获取管线**（站点有 WAF，纯脚本被拦；用浏览器会话内执行完成）：

```
页面内 POST /law-search/search/list        → 按标题精确检索，取 bbbs（文档 id）
页面内 GET  /law-search/search/flfgDetails → 校验版本（sxx=3 有效）与公布/施行日期
页面内 POST /law-search/download/batch     → 取 OSS 预签名直链（公网可达）
分片取回 docx 字节 → 落盘 → 质检 → 条级切分 → 片段 JSONL
```

**切条规则**（`scripts/docx_to_articles.py`，纯标准库解 docx）：段落以「第X条」开头开新条，配**条号单调递增**约束（防止「本法第X条」类行首引用误切），非条首段落并入当前条，编/章节标题丢弃，支持「之一/之二」修正案后缀。

**合入纪律（append-only）**：v1 的 14,212 行一个字节不动、id 不变（真实金标 gold_ids 绑定这些 id）；新片段走 **900000+ 保留 id 命名空间**；质检用与 v1 同一把污染标记门，但豁免 30 字下限（该规则过滤的是公报 PDF 残渣；官方 docx 零残片，短条文是真实法条）。

## 3. 实测数字（v2 语料 = 16,523 条，如实并列）

| 口径 | v1 语料（14,212） | v2 语料（16,523） |
|---|---|---|
| 真实金标 38 题 hybrid R@5 / MRR | 44.7% / 0.312 | **39.5% / 0.246** |
| 真实金标深度 R@30 | 78.9% | 76.3% |
| 旧合成金标 177 题（v1 出题）R@5 | 98.9% | 98.3%（唯一性约束被新法条部分打破，预期内） |
| v2 新合成金标 200 题 R@5 / MRR | — | **100.0% / 0.995** |

**必须如实说明**：真实金标在新语料上**下降 5.2pt**（少命中 1 题、排名整体后移）——新增的刑法/刑诉法等条文与既有问句主题竞争，检索变难了。这是语料覆盖扩大的真实代价，不是回归 bug：v1 的 44.7% 口径在 v1 语料上依然可复现。深度口径显示 R@30 仍达 76.3%，重排空间（v0.2 主线）不变。

## 4. 后续计划（按优先级）

1. **真实金标扩容（38 → 200）**：民法典/刑法入库后，此前因语料受限无法入金的选题可以进了；按 build_real_gold.py 流程逐题 LLM 核验 + 证据逐字校验 + 人工复核闭环。
2. **公报源污染行替换**：治安管理处罚法、民诉法、公司法等公报双栏污染法，逐部用 flk 官方版本追加干净行（append-only 不破坏 v1 id），并在质检报告里标注旧行为污染候选。
3. **逐行解析质量分**（backlog candidate-011）：给 v1 公报源行打质量旗标，输出按法聚合的质检报告，为替换排期。
4. **多版本口径**：同一法律多版本并存的检索竞争问题，需要在 Citation 输出中带版本元数据（meta.effective），由上层按时间有效性过滤。
5. **v2 数字进 README/网站**：待金标扩容后一并更新（避免每步都改口径文案）。
